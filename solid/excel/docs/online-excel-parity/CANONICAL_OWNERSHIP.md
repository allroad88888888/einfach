## 1｜裁决摘要与依据

2026-07-19 完成一次战略裁决，采用 11-agent 工作流：**6 路代码审计 + 3 评审 + 2 对抗批评者**；三评审一致采纳 **"混合翻转 C-modified"**。裁决依据是代码真值，不是设计愿望：

1. **视口事实从未真实活在 backend。** hidden 行列、freeze、filter 可见性、protection 在纸面上是 backend canonical，实际只活在 `static-backend` 的内存态；两个引擎（`rust/excel-core`、`vanilla/excel-core-ts`）和 worker RPC 从未建模它们；引擎没有任何公式读取 hidden（SUBTOTAL 101-111 被折算为 1-11）。**〔2026-07-22 二次翻转已使加粗这句过期：引擎现读两个隐藏集，`SUBTOTAL(1-11)` 只读筛选集、`(101-111)` 两个都读；隐藏行与筛选可见性因此翻回引擎——见顶部二次翻转块。〕**
2. **引擎侧 undo 是死代码，快照原语已在线。** Rust `undo.rs` 是零调用方死代码；wasm 快照原语（`snapshot_sparse` / `restore_sparse` ADDITIVE、format snapshot、persistence v1）已在 worker 协议线上，但从未被组装成 `undoTransaction` 端口。
3. **TS worker 存在 fail-open 假 ACK。** 结构操作 no-op 却返回 `true` 等路径会伪造成功。
4. **static-backend 存在实锤 bug。** 插入/删除行列不平移 merge。

裁决结论：与其继续"等两个引擎把视口事实和事务日志补齐"，不如按代码真值翻转归属——视口事实归 UI-core，数据事实归引擎，undo 归宿主编排，WASM 收敛为唯一真实后端口径。

## 2｜新口径定义（四类归属）

| 归属类别             | 定义                                                                                                                            | 覆盖事实                                                                                                                     |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **引擎数据事实**     | 引擎（经 backend 端口）是唯一权威；UI-core 只读投影                                                                             | 值、公式、重算、结构操作、排序执行、removeDuplicates、paste 数据、**隐藏行可见性、筛选可见性**（2026-07-22 二次翻转）、行高列宽（as-built）；cell format / named ranges 维持 backend canonical 合同形状 |
| **UI-core 视图事实** | UI-core 是唯一权威；backend 端口降级为**可选持久化钩子**，缺失时功能不降级                                                      | freeze、**隐藏列**、protection 门禁（隐藏行 / 行高列宽 / 筛选可见性已归引擎，见顶部二次翻转）                                 |
| **adapter overlay**  | 合同形状维持 backend canonical，worker 路径以 host-overlay 落地（validation / conditional-formatting 既有模式即先例，就此转正） | merge（worker 路径）、条件格式、数据验证规则存储                                                                             |
| **混合**             | 同一功能点内不同事实分属不同类别；逐项注明拆分                                                                                  | 见总账表内注明                                                                                                               |

横切规则：

- **undo = 宿主编排**：UI-core history 负责编排，引擎快照原语负责执行；**不建引擎事务日志**，`undo.rs` 死代码不复活。
- **WASM 是唯一真实后端口径**；TS worker 降级为 **fail-closed 开发后备**——不支持的能力必须显式 `false` / 隐藏入口，禁止假 ACK。"Worker parity"类闭环条件一律收敛为对 WASM 单口径验证。
- 只读投影 atom 形状不变；翻转对下游消费者透明，但投影消费者必须显式化（见 §6）。

## 4｜确认的设计点（对抗批评者坐实）

1. **结构操作 undo 需全表非空公式快照。** 结构操作会把失效引用改写为 `#REF!` 哨兵，该改写不可逆，增量 delta 无法恢复原公式；必须在结构操作前捕获全表非空公式快照（legacy `STRUCTURAL_SNAPSHOT_MAX=2000` 是既有先例）。
2. **异步公式 settle 与 history 见证需分离计数。** 异步自定义公式 settle 会无条件 bump revision；history 的严格 revision 见证若与其共用同一计数器会被异步 settle 误伤，两者必须分离。
3. **deleteSheet 级恢复需注册态重放协议。** persistence v1 快照不含自定义公式注册表、named values、订阅；sheet 级恢复必须在 restore 后重放注册态，否则恢复出的表是残缺的。
4. **history 模块需新增 local-replay 分支。** 视图事实（freeze/hidden/filter 可见性/protection；行高列宽经 as-built 修正未翻转）翻转为 UI-core canonical 后，其 undo 不经引擎快照，由 history 的 local-replay 分支在 UI-core 内闭环（已落地，protection 按 Excel parity 例外不入历史）。

   > **filter 可见性的例外形状（2026-07-21，#27 落地后补记）**：筛选隐藏集**不产生自己的 history 条目**——它是规则的派生结果，它的 undo 就是筛选规则本身的 undo（这也是 §3 坚持两个集合的第三条硬约束：用户对被筛行执行 `Unhide Rows` 在 Excel 里不解筛选）。它用到 local-replay 的地方只有一处：结构操作（插入/删除行）会吞掉删除带内的成员，那没有逆运算，所以结构条目挂一份 `VIEWPORT_FILTER_HIDDEN_REPLAY_KEY` 的**快照式 local side payload**，与手动隐藏集同一理由、同一机制。**〔2026-07-22 更新〕**：筛选侧 local side payload 已随隐藏行下沉 E8 **删除** —— 筛选是纯投影、无自己的写路径，其结构 undo 改由引擎快照 `restoreFilters` 恢复、provider 从 `readSheetHiddenState.filterRows` re-hydrate（`reconcileFilterHiddenFromEngine`）；筛选侧**前向**结构位移保留。手动侧仍保留 local-replay（applier 经 `feedAndReconcileHiddenRows` 把恢复后的集合重喂引擎）。
   >
   > **〔2026-07-22 二次更新 —— 筛选 apply/clear 本身可撤销（Excel parity）〕**：上文"筛选隐藏集不产生自己的 history 条目"针对的是**派生集合**；**筛选规则 apply/clear 本身现在是一条可撤销事务**（照 Office Excel 实测：施加/清除 AutoFilter 可 Ctrl+Z）。这**不新建机制**，复用 E8 的引擎快照：`runFilterSortMutationAtom` 发 `recordHistory: true`，adapter 只在筛选**真的变化**（before ≠ after）时括 `snapshotFilters` 前后像、推一条**只带 `filtersSnapshot` 的 filter-only 事务记录**并在 ACK 里回 `historyRecorded`；UI-core 仅在该 verdict 为 true 时推**一条配对的 `filter.set` history 条目**（空筛选/no-op 与 Reapply 两侧都不记，`recordHistory:false`），两栈按位置对齐（与 Table 定义同一契约）。undo/redo 经同一 `restoreFilters`（worker）/ 反向 delta（static）恢复引擎筛选，provider re-hydrate 两个渲染缓存：`viewportFilterHiddenAtom`（隐藏集）与 `filterSortStateAtom`（规则，经 `reconcileFilterSortRulesFromEngineAtom` set-or-remove）。**Reapply 仍不进 undo**（identity 非 undo 步）。

## 7｜张力裁决（2026-07-19 主控裁决，原"已知张力"三项全部关闭）

1. **SUBTOTAL 101-111 与 hidden —— 裁决：宿主喂可见性给引擎。** #32 实现时采用"求值上下文推送"：宿主把 per-sheet 隐藏行集合作为只读求值输入喂给引擎（可选推送端口或求值参数），引擎不建 hidden 模型、不感知隐藏来源。不采用宿主侧求值（避免在宿主复刻聚合语义）。在 #32 落地前，现状"101-111 折算为 1-11"记为已知 conformance gap，不阻塞其他项。

   > **勘误（2026-07-21，#27 落地后按代码订正）**：本条原文写"手动/filter 同一集合"，**已不成立**。#27 证明一个集合在架构上表达不了 Excel 的两档规则——`SUBTOTAL(1-11)` 必须**包含**手动隐藏行、**排除**筛选隐藏行，合并集之后来源信息永久丢失。引擎现持**两个**独立的 per-sheet 集合，经**两个**独立端口推送（`setEvalHiddenRows` 手动 / `setEvalFilterHiddenRows` 筛选，后者为 #27 新增的纯加法端口），并配**两个**失效 epoch，使推送手动隐藏不脏化全工作簿的 1-11 公式。"引擎不建 hidden 模型、不感知隐藏语义"这半句仍然成立：引擎只按集合跳过行，不知道行为什么被隐藏。旧口径的"同一集合"三处硬约束（SUBTOTAL 两档、复制语义不对称、unhide 不得解筛选）任一条都足以否掉，详见 [design-filter-hidden-rows.md](./design-filter-hidden-rows.md) §3 与 §6。

   > **二次勘误收口（2026-07-22，隐藏行下沉落地后）**：本条标题"宿主喂可见性给引擎"已被**隐藏行下沉**（`design-engine-hidden-rows.md`，E0–E8）超越 —— 引擎不再"被喂"，而是**拥有**手动隐藏（`Sheet.hidden_rows`）与筛选（`SheetAutoFilter` = 规则 + 派生隐藏集）并自己求值谓词。两个 `setEval*HiddenRows` 端口退化为 INV-4 加法式历史包袱：手动侧 `setEvalHiddenRows` 仍承载乐观-对账 feed（整集替换），筛选侧 `setEvalFilterHiddenRows` 已被适配器**弃用**（改走 `applyFilter` + `snapshotFilters`/`restoreFilters`）。隐藏行与筛选可见性的归属随之从 UI-core 翻为**引擎**，见顶部二次翻转块与 §3 表 #03 / #29。
2. **#07 大纲层级元数据 —— 裁决：UI-core canonical。** 分组结构不参与计算、无 xlsx/持久化需求；层级深度 cap 8（对齐 Excel），折叠效果复用 hidden 的本地全量集合；backend 端口为可选持久化钩子。#07 归属已在 §3 表更新为 UI-core 视图事实。
3. **#11 column-widths 附载 —— 张力消解。** 行高列宽经 as-built 修正维持引擎数据事实（未翻转），column-widths 粘贴回归单一引擎域，无跨域原子性问题；唯一要求：paste 事务记录捕获 before-widths（有界：粘贴列数）以纳入宿主编排 undo。
